# Вступ



Частиною життєвого циклу будь якої системи керування є доопераційні стадії, які завершуються введенням в дію на об'єкті. Ці стадії як правило включають розробку вимог, створення проекту, реалізацію та введення в дію. Саме процесами цих стадій більшою мірою займаються інженери.

У даному курсі програмна інженерія передбачає різноманітні діяльності в процесах життєвого циклу програмного забезпечення систем керування. Але для таких систем великою, а навіть більшою мірою характерні діяльності по розробці, впровадженню та експлуатації апаратних засобів. Системи на базі Інтернету речей не є виключенням і передбачають як роботи над програмною, так і апаратною частиною. Курсова робота є певним наближенням до такої проектної діяльності, так як відтворює основні процеси доопераційних стадій життєвого циклу, хоч і не в повному обсязі. Слід відмітити, що на старших курсах проектуванню систем керування приділяється велика увага як на рівні бакалаврату так і в магістратутрі, а кваліфікаційна робота бакалавра передбачає розробку проекту для автоматизованих системи керування технологічними процесами (АСКТП). Тому там будуть розглядатися методи, інструменти та стандарти, які характерні саме для розробки АСКТП. Для даного ж проекту характерне суттєве спрощення процесів проектної діяльності.

# 1. Мета і завдання курсового проектування



**Мета курсової роботи** – зміцнення і поглиблення теоретичних знань з дисципліни “Програмна інженерія в системах управління” а також набуття практичних навичок в розробці проектів IoT-рішень та впровадженні їх частин в умовах командної роботи.

Курсова робота передбачає розробку проекту та впровадження його частин для IoT рішення в різноманітних областях життєдіяльності людини, у тому числі автоматизація будинків, будівель, ЖКХ, транспорті, торгівлі, дозвіллі і т.д. У якості класичного прототипу структури IoT-рішення розглядається система, яка включає в себе наступні апаратні частини:

- Raspberry PI у якості центрального компоненту системи
- підключену до GPIO периферію - датчики, виконавчі механізми, інші елементи
- за необхідності інші пристрої, підключені через цифрові шини GPIO, USB або Ethernet
- додаткові матеріали та монтажні компоненти
- мобільні пристрої (смартфони, планшети, тощо)
- шлюзи, маршрутизатори для виходу в Інтернет
- інші компоненти за необхідності

- мобільні браузери та застосунки для роботи з MQTT

# КУРСОВА РОБОТА

## Контроль електроспоживання в готелі

------

## ВСТУП

У сучасних умовах енергозбереження є одним із ключових факторів ефективного функціонування підприємств сфери обслуговування, зокрема готельного бізнесу. Високі витрати на електроенергію, необхідність оптимізації ресурсів та підвищення рівня автоматизації зумовлюють актуальність впровадження інтелектуальних систем контролю електроспоживання.

Системи на базі Інтернету речей (IoT) дозволяють здійснювати моніторинг, аналіз та керування електроспоживанням у режимі реального часу. Вони забезпечують зменшення витрат, підвищення енергоефективності та покращення якості обслуговування клієнтів.

Метою даної курсової роботи є розробка IoT-рішення для контролю електроспоживання в готелі з використанням сучасних апаратних і програмних засобів.

------

## 1. РОЗРОБКА ВИМОГ ДО СИСТЕМИ ТА ПЗ

### 1.1 Загальний опис системи

Проектована система призначена для збору, обробки та аналізу даних про електроспоживання в готелі. Вона дозволяє:

Система повинна передбачати виконання наступних функцій:

- неперервне вимірювання електроспоживання (Вт, кВт·год) з періодичністю не більше 1 секунди
- відображення поточного значення електроспоживання:
  - на локальному WEB-інтерфейсі (1 раз/сек)
  - у мобільному застосунку
  - у Telegram-боті (за запитом або періодично)
- архівування даних:
  - збереження середнього значення за кожні 10 секунд у локальну базу даних
  - збереження історії за добу, тиждень, місяць
- візуалізація даних:
  - побудова графіків споживання за останні 60 секунд (реальний час)
  - тренди за годину/день/місяць
  - відображення у Google Sheets
- оповіщення:
  - при перевищенні встановленого ліміту електроспоживання
  - відправка повідомлень у Telegram та на email
- формування звітів:
  - автоматично раз на годину або за запитом
  - у вигляді таблиць та графіків
  - з показниками мінімального, максимального та середнього споживання
- дистанційне керування:
  - включення/вимкнення електропристроїв (за наявності реле)
  - встановлення лімітів споживання

Система складається з:

- центрального вузла (Raspberry Pi);
- датчиків струму (PZEM-004T або ACS712);
- мережевих компонентів;
- хмарних сервісів.

------

### 1.2 Вимоги до функцій та задач

Система повинна виконувати такі функції:

- вимірювання напруги, струму та потужності;
- передача даних у реальному часі;
- збереження історії споживання;
- формування графіків;
- надсилання повідомлень про перевищення норм;
- дистанційне керування навантаженням.

------

### 1.3 Вимоги до видів забезпечення

**Апаратне забезпечення:**

- Raspberry Pi 3/4;
- датчики PZEM-004T або ACS712;
- реле для керування навантаженням;
- Wi-Fi маршрутизатор.

**Програмне забезпечення:**

Node-RED для розробки логіки системи

Node-RED Dashboard для WEB-інтерфейсу

база даних (MariaDB або SQLite)

Google Sheets для аналітики

Telegram-бот для віддаленого контролю

IoT MQTT Panel для мобільного керування

### 2.1 Технічна структура системи

Система має трирівневу архітектуру:

1. Edge-рівень (Raspberry Pi + датчики)
2. Серверний рівень (база даних)
3. Клієнтський рівень (веб-інтерфейс, мобільні пристрої)

------

### 2.2 Схеми підключення

Датчик PZEM-004T підключається до Raspberry Pi через UART інтерфейс.
ACS712 підключається до аналогово-цифрового перетворювача.

Реле підключається до GPIO для керування електроприладами.

------

### 2.3 Опис апаратних засобів

- **Raspberry Pi** — центральний контролер
- **PZEM-004T** — вимірювання електроенергії
- **ACS712** — датчик струму
- **Реле** — керування навантаженням

------

### 2.4 Програмна структура

Система використовує Node-RED для:

- обробки даних;
- створення потоків;
- візуалізації.

MariaDB використовується для збереження даних.
