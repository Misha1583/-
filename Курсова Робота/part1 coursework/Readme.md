# Вступ



Частиною життєвого циклу будь якої системи керування є  доопераційні стадії, які завершуються введенням в дію на об'єкті. Ці  стадії як правило включають розробку вимог, створення проекту,  реалізацію та введення в дію. Саме процесами цих стадій більшою мірою  займаються інженери.

У даному курсі програмна інженерія передбачає різноманітні діяльності в процесах життєвого циклу програмного забезпечення систем  керування. Але для таких систем великою, а навіть більшою мірою  характерні діяльності по розробці, впровадженню та експлуатації  апаратних засобів. Системи на базі Інтернету речей не є виключенням і  передбачають як роботи над програмною, так і апаратною частиною. Курсова робота є певним наближенням до такої проектної діяльності, так як  відтворює основні процеси доопераційних стадій життєвого циклу, хоч і не в повному обсязі. Слід відмітити, що на старших курсах проектуванню  систем керування приділяється велика увага як на рівні бакалаврату так і в магістратутрі, а кваліфікаційна робота бакалавра передбачає розробку  проекту для автоматизованих системи керування технологічними процесами  (АСКТП). Тому там будуть розглядатися методи, інструменти та стандарти,  які характерні саме для розробки АСКТП. Для даного ж проекту характерне  суттєве спрощення процесів проектної діяльності.

## 1.1 Загальний опис проектованої системи

Система контролю електроспоживання в готелі призначена для збору, обробки, відображення та аналізу даних про споживання електроенергії в реальному часі. Система повинна забезпечувати моніторинг споживання електроенергії по окремих зонах або номерах готелю, архівування даних, формування звітів та оповіщення при перевищенні встановлених лімітів.

Керування та контроль системи повинні здійснюватися через локальний WEB-інтерфейс, мобільний застосунок та Telegram-бот.

## 1.2 Вимоги до функцій та задач

Система повинна передбачати виконання наступних функцій:

- неперервне вимірювання електроспоживання (Вт, кВт·год) з періодичністю не більше 1 секунди
- відображення поточного значення електроспоживання:
  - на локальному WEB-інтерфейсі (1 раз/сек)
  - у мобільному застосунку
  - у Telegram-боті (за запитом або періодично)
- архівування даних:
  - збереження середнього значення за кожні 10 секунд у локальну базу даних
  - збереження історії за добу, тиждень, місяць
- візуалізація даних:
  - побудова графіків споживання за останні 60 секунд (реальний час)
  - тренди за годину/день/місяць
  - відображення у Google Sheets
- оповіщення:
  - при перевищенні встановленого ліміту електроспоживання
  - відправка повідомлень у Telegram та на email
- формування звітів:
  - автоматично раз на годину або за запитом
  - у вигляді таблиць та графіків
  - з показниками мінімального, максимального та середнього споживання
- дистанційне керування:
  - включення/вимкнення електропристроїв (за наявності реле)
  - встановлення лімітів споживання

## 1.3 Вимоги до видів забезпечення

### Вимоги до апаратного забезпечення

Необхідно використання наступних засобів:

- Raspberry Pi 4/5 або аналогічний одноплатний комп’ютер
- датчики струму/напруги (наприклад ACS712, PZEM-004T)
- модулі реле для керування навантаженням
- підключення до мережі Internet (WiFi або Ethernet)
- смартфон або планшет (Android/iOS)
- експлуатація у приміщенні (готель)

### Вимоги до програмного забезпечення

- Node-RED для розробки логіки системи
- Node-RED Dashboard для WEB-інтерфейсу
- база даних (MariaDB або SQLite)
- Google Sheets для аналітики
- Telegram-бот для віддаленого контролю
- IoT MQTT Panel для мобільного керування
